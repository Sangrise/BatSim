BatSim User Manual

BatSim is a PSpice-style schematic editor combined with a Python battery & BMS simulation engine. Press F1 at any time to reopen this manual. The same manual covers the GUI, the command-line interface, and the extension points (custom battery models, cell data files, external SOC algorithms).

1. What BatSim does

BatSim couples a schematic editor with a Python numerical solver:

  • Editor — drag components, draw wires, set parameters.
  • Solver — modified-nodal-analysis (MNA) DC and transient engine with Newton iteration for non-linear devices and battery models.
  • Battery / BMS — pluggable battery models (Rint, Thevenin, n-RC, SPM, data-driven) plus optional BMS blocks for protection, balancing and SOC estimation.
  • CLI & sweeps — run any simulation from the terminal so you can sweep parameters and pick the best operating point without opening the GUI.

2. Window layout

  • Components dock (left) — drag any item onto the canvas.
  • Canvas (centre) — schematic editor. Wheel = scroll, Ctrl+wheel = zoom, drag empty area = rubber-band select.
  • Inspector dock (right) — parameters of the currently selected component.
  • Waveforms dock (bottom) — appears after the first transient run. Hosts one or more plot panels.
  • Status bar — context hints, simulation summary.
  • Menus — File, Edit (copy/paste/blocks), Simulate, Help.

3. Five-minute quick start

  1. Drag a V, an R, a C and a GND from the palette.
  2. Click on a yellow pin and drag onto another pin to draw a wire (a green dashed preview line follows your cursor; it turns solid bright green when releasing will create a valid connection).
  3. Click the V source — the right-hand Inspector shows its V field. Type 5 and press Enter.
  4. Press Ctrl+R, choose Transient, set t_end = 0.05, dt = 0.0005, press OK.
  5. The bottom Waveforms dock opens with V(N1), V(N2), I(V1) curves.

6. Wiring — the full workflow

Drawing a wire

Two interchangeable methods:

  • Drag — press on a pin (small yellow square at the component edge), drag, release on another pin.
  • Click-click — click the start pin, then click the end pin. Press Esc to abort.

While dragging, an orthogonal preview line follows the cursor:

  • Faint dashed — cursor is in empty space; releasing here will not create a wire.
  • Bright solid — cursor is over a valid target (a pin or an existing wire); releasing here connects.
Important: a wire is created only when the release lands on a pin or on an existing wire. If you release in empty space, nothing happens — there is no floating wire end.

Avoiding component bodies

The router treats every other component on the canvas as an obstacle and uses a Manhattan (orthogonal) detour when needed. The endpoint components are also treated as soft obstacles so the wire can only enter through the pin, never cut across the body. Example: connecting the right pin of a left-side voltage source to the right side of an R-(R||C) network detours below the inner R rather than crossing it.

Editing wire bends

Select a wire (it turns white) — every internal segment shows an orange square handle at its midpoint. Drag any handle:

  • Horizontal segments slide vertically; vertical segments slide horizontally. The grid pitch is 20 px.
  • If a segment is the only one between a pin and the rest of the wire, BatSim automatically inserts an L-shaped elbow so that the pin endpoint stays anchored. You can therefore freely move any bend, including those right next to the pin.
  • Selecting "Delete" on a wire removes the whole wire (not just one segment).

Parallel tap (T-junction)

To branch off an existing wire:

  1. Start a wire from a pin.
  2. Drop the free end onto an existing wire.
  3. BatSim places a small JUNCTION dot exactly on the wire and attaches the new wire to it. The original wire is not split — it stays as a single segment underneath.
A JUNCTION must always lie on a wire. Dragging it slides it along the host wire only — it cannot leave the wire. If you delete the host wire, the junction (and any wires connected to it) are removed automatically.

Wire crossings

When two wires cross, BatSim shows:

  • A green dot if they share an electrical node (galvanic connection through a JUNCTION).
  • A small arc / hop if they merely cross visually but are on different nodes.

7. Moving, rotating, copying

Moving

Drag a component to move it. Wires follow automatically. Movement is snapped to the grid.

Rotating & mirroring

  • Keyboard: R to rotate +90°, M to mirror horizontally.
  • Mouse: right-click a component → Rotate 90° / −90° / Mirror.
  • Wires stay connected. When a pin's scene position shifts after rotation, the component is auto-translated so the wire endpoint follows the pin instead of detaching.

Copy / paste

  • Ctrl+C copies the selected components plus every wire that lies entirely between them.
  • Ctrl+V pastes them centred at the current view middle, with new component IDs.
  • Cross-instance paste works too — the clipboard text starts with BATSIM: followed by JSON.

8. Reusable blocks

A "block" is a saved sub-schematic that you can drop back onto any canvas later.

  1. Select the components and wires you want to reuse.
  2. Edit → Save selection as block… (or Ctrl+G), enter a name.
  3. The block is written to ~/.batsim/blocks/<name>.json.
  4. Edit → Insert block shows every saved block. Choosing one pastes it at the current view centre with fresh IDs.
  5. Edit → Open blocks folder opens that directory in your file browser, so you can email/share blocks easily.

9. Inspector

  • Numbers — typed values are converted to float automatically; scientific notation (1e-3) is OK.
  • Booleans — appear as a check-box.
  • Lists / dictionaries (e.g. an OCV-SOC table) — read-only in the inspector. Edit the underlying JSON in data/cells/ instead.
  • Confirm a value with Tab or Enter.

10. Battery models & cell presets

A BATTERY component combines a model (the equation set) with optional cell preset data (the parameters of a real cell).

DropdownMeaning
cell (preset) Every JSON in data/cells/ or ~/.batsim/data/cells/. Selecting one fills in capacity, R0, OCV table, etc. and may override the model name. Ships with 63 Ah NCM and LFP presets out of the box.
model Any model registered in the plug-in registry. Built-ins: Rint, Thevenin (1-RC), n-RC, SPM, DataDriven.
chemistry Selects the OCV curve used by Rint / Thevenin / n-RC. NCM (gentle slope 3.50→4.20 V), LFP (~3.30 V plateau across 20–90 % SOC), NCA, LCO, LTO (1.5–2.85 V), Generic. DataDriven uses the cell's own ocv_table and ignores this field.

Choosing a model

  • Rint — fastest. V_t = OCV(SOC) − I·R0.
  • Thevenin — adds one RC pair for short-term polarisation.
  • n-RC — multiple RC pairs (fast + slow). Typical BMS validation level.
  • SPM — simplified single-particle electrochemistry.
  • DataDriven — drop in any cell using only an OCV-SOC table and optional RC pairs (no Python required).
Floating circuits / auto-ground (BUS recommended)
Drop a BUS component (mode = Grid / PLoad / ILoad) on the schematic and its negative pin automatically becomes the system 0 V reference — no GND symbol required.
Grid models a stiff voltage source (a transformer-coupled mains tie), PLoad a constant-power load, ILoad a constant-current load. All three are the same symbol; switch with the mode dropdown in the inspector.
For backward compatibility with sheets that have neither GND nor BUS, the first PCONST/ICONST/IPATTERN/I or BATTERY's negative pin is used as the anchor.

TR — Ideal turns-ratio coupler (AC- or DC-capable)

A 4-pin component (p+, p−, s+, s−) that enforces V(p+)−V(p−) = n · (V(s+)−V(s−)) (where n is the primary/secondary turns ratio). Power balance gives I_s = −n · I_p.

The engine is time-domain, so a sinusoidal input is transformed instantly — TR works as an AC voltage-ratio coupler. Magnetising and leakage inductance are not modelled. Each side still needs its own GRID/BUS/GND reference, otherwise the secondary mesh is singular.

AC chain — GRID · TR · PCS

The canonical grid-tied ESS topology GRID(AC) → TR → PCS(AC↔DC) → BATTERY is drawn directly:

  • GRID — 2-pin sine source. Parameters: V_rms, freq [Hz], phase_deg, bias. Pin 1 (neutral) is auto-anchored to node 0.
  • PCS — 4-pin converter (AC+, AC−, DC+, DC−). 9 modes are supported and every charge/discharge profile is entered directly in the PCS inspector.
    modedescriptionkey params
    V_DCstiff DC voltage source (CV charger)V_DC_set
    I_DCstiff DC current source (CC charger)I_DC_set
    P_DCconstant DC powerP_DC_set

    CYCLEJSON step list executed sequentiallycycle_steps, cycle_repeat

    Sign convention — + = charging, − = discharging. cycle_steps is a JSON array of single-mode steps with optional terminators (max_time, V_max, V_min, I_term). Example:

    [{"mode":"CC","I":10,"V_max":3.6,"max_time":600},
 {"mode":"REST","time":300},
 {"mode":"CP","P":-50,"V_min":2.5,"max_time":900}]

    cycle_repeat=N repeats the list N times (0 = forever). The AC side is modelled as an equivalent constant-power load with efficiency η. Both AC− and DC− pins are auto-anchored to node 0; v1 does not model galvanic isolation — for isolated transforms put a TR on the AC side and use it for voltage scaling only.

  • dt guidance — for ≥20 samples per AC cycle use dt ≤ 1/(20·f) (50 Hz → 1 ms, 60 Hz → 0.83 ms).

11. BMS blocks

The batsim.bms package ships protection, cell-balancing, SOC-estimator and pack controller logic that you can attach to a battery in a Python plug-in or driver script. Use batsim list-bms to see what is available, and ~/.batsim/plugins/ to drop in your own.

12. Probes & what gets plotted

  • Drop a PROBE on any net to add a V(P1) signal. The probe label increments (P2, P3, …) for each new instance.
  • Insert an IPROBE in series with a wire. The two pins act as a 0 V "shunt"; its current is exposed as I(IP1).
  • If you do not place any probe, every node voltage and every voltage-source current is exposed automatically — handy for first-pass exploration but verbose for big circuits.

Charge / discharge pattern components

  • ICONST — constant-current sink/source. Param I (A; positive = current flows pin0 → pin1). Use across a battery for constant-current cycling.
  • PCONST — constant-power load. Param P (W; positive = sink). Solved by the Newton-Raphson loop (clamped to |V| > 0.5 V for startup stability).
  • IPATTERN — programmable current source driven by a CSV. Params: csv file path (use the "…" picker in the inspector), scale, repeat, and a fallback I when the file is missing. CSV format is two columns time_sec, value (no header; # lines treated as comments): 
    # discharge profile
0,    0
60,   1.0    # 1 A discharge for 1 hour
3660, 0
3700, -2.0   # then 2 A charge
Probes can be moved, rotated and copied just like regular components — wires stay attached.

13. Running a simulation

Simulate → Run… (or Ctrl+R) opens the dialog. Inline help describes the selected mode.

modemeaningoutput
DC operating point Bias point at t=0 only — capacitors open, inductors shorted, AC sources held at their DC value. Snapshot of node voltages (message box).
Transient Time-domain integration 0→t_end with step dt. Newton iteration handles non-linear devices and battery models. Full waveforms in the Waveforms dock.

Auto from PCS cycle button — next to t_end. Sums each PCS's cycle_steps (max_time·time) × cycle_repeat and uses the largest across all PCS components.

PCS cycle ≠ Run t_end. The cycle defines what to do; t_end defines how long to simulate. They are independent: if t_end is shorter the run stops mid-cycle; if longer the PCS sits in DONE state (I=0) after the cycle finishes. cycle_repeat=0 (infinite) requires a manual t_end.
Battery current sign convention: positive = discharge (current leaves the battery's + terminal). PCS setpoint sign convention is separate: + = charge, − = discharge.

14. Waveform panels

  • Auto V/I split — after the first simulation the default panel is automatically replaced by a Voltage panel on top and a Current panel below, each driving its left axis.
  • + Add plot — adds another panel below the current ones. Each panel has its own per-signal axis state.
  • Split V / I — discards the current panel layout and rebuilds the auto V/I split.
  • Dual Y axes — click a row in the side list to cycle the signal through Off → L (left axis) → R (right axis) → Off. Left-axis traces are solid, right-axis traces are dashed and tagged "(R)" in the legend, so V and I can share a single panel when needed.
  • All→L / None — drop every signal on the left axis or turn them all off in one click.
  • × Remove — delete a panel (at least one is always kept).
  • Drag the splitter bars to resize panels vertically.

15. Command-line interface

Every operation has a CLI counterpart so you can script sweeps and batch runs without opening the GUI.

batsim ui                              # Launch the GUI
batsim list-models | list-cells | list-bms | list-soc

batsim run myproj.batsim --t-end 60 --dt 0.001 --csv out.csv
batsim run myproj.batsim --dc

batsim cell-test --cell INR18650-25R --r-load 1.0 --t-end 3600 \
                 --csv discharge.csv

batsim sweep examples/sweep_example.json --csv sweep.csv --maximise

batsim soc-eval --script examples/external_soc_example.py \
                --algorithm CoulombCounter SimpleEKF OCVLookup \
                --cell INR18650-25R --current 1.0 --t-end 1800 \
                --csv soc.csv

Sweep config (JSON)

{
  "runner": "battery_profile_run",
  "base":   {"cell": "INR18650-25R", "I_profile": 1.0,
             "t_end": 600, "dt": 1.0},
  "grid":   {"model_name": ["Rint","Thevenin","n-RC"],
             "soc0":       [0.5, 0.8, 1.0]},
  "metric": "min_voltage"
}

Supported metrics: min_voltage, final_soc, energy_Wh. Use --maximise to flip the direction.

16. Extending BatSim

Three independent extension points, in increasing complexity.

16.1 Cell preset (data file only)

Add data/cells/MyCell.json (or ~/.batsim/data/cells/MyCell.json for a per-user file):

{
  "name": "MyCell-2Ah",
  "model": "DataDriven",
  "params": {
    "capacity_Ah": 2.0, "soc0": 1.0, "R0": 0.025,
    "RC_pairs": [[0.012, 1500], [0.020, 8000]],
    "ocv_table": [[0.0, 2.9], [0.5, 3.7], [1.0, 4.18]]
  }
}

Restart BatSim → it appears in the Inspector's cell (preset) dropdown and in batsim list-cells.

16.2 New battery model (Python plug-in)

Drop a Python file into ~/.batsim/plugins/:

from batsim.models.base import BatteryModel
from batsim.plugins.registry import register_battery_model

@register_battery_model("MyChem")
class MyChemModel(BatteryModel):
    def __init__(self, capacity_Ah=2.0, soc0=1.0, alpha=0.5):
        super().__init__(capacity_Ah, soc0)
        self.alpha = alpha
    def terminal_voltage(self, t, dt):
        return 3.0 + self.alpha * self.soc

Set the env var BATSIM_PLUGIN_PATH to add other plug-in directories. Use batsim list-models to confirm.

16.3 External SOC algorithm

Any my_soc.py, anywhere on disk:

from batsim.soc import register_soc_algorithm

@register_soc_algorithm("MyEKF")
class MyEKF:
    def __init__(self, capacity_Ah=2.5, soc0=1.0): ...
    def step(self, I, V, dt) -> float:
        ...
        return self.soc

Even without the decorator, any class whose method signature is exactly step(self, I, V, dt) is auto-registered.

batsim soc-eval --script my_soc.py \
                --algorithm MyEKF CoulombCounter \
                --cell INR18650-25R --current 1.0 --t-end 1800

The output table reports each algorithm's RMSE and final SOC.

17. Troubleshooting

SymptomCause / fix
"Singular matrix" simulation error An isolated node or no GND. Make sure every node has a DC path to GND. Use a probe to verify.
Battery voltage stays flat capacity_Ah too large, or t_end too short. Verify with batsim cell-test … --csv discharge.csv.
Wire visibly cuts through a component Should never happen now — both endpoint and middle components are obstacles. If it does, file an issue with a saved .batsim file.
JUNCTION drifts off its wire Cannot happen — JUNCTIONs are constrained to lie on their host wire. If the wire is deleted, the JUNCTION is removed too.
New model / cell not visible Restart BatSim. Data files must live under data/cells/ or ~/.batsim/data/cells/.
External SOC script does not register Without the decorator, the method must be exactly step(self, I, V, dt) (no kwargs, no extra parameters).
